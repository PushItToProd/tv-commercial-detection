Project walkthrough

TV Commercial Detector

A home-built system that watches a live race broadcast streaming in a browser tab, works out — several times a minute — whether what's on screen is racing or a commercial break, and flips an HDMI matrix to a different input for the duration of the break.

Firefox extension (MV2) FastAPI + Python 3.14 OpenCV template matching llama.cpp vision LLM HDMI matrix over USB serial YouTube TV · HBO Max
01 — ARCHITECTURE

Four processes and a piece of hardware

Nothing leaves the local network. The browser sees the stream, a local server does the thinking, a local GPU runs the model, and a serial bridge drives the matrix.

02 — THE LOOP

What happens every few seconds

One pass of the loop, from pixels on screen to (maybe) a relay clicking over in the matrix.

~3 s

Extension default is 10 s — too slow to catch the start of a break. Real ceiling is GPU inference speed.

03 — CLASSIFICATION

A cheap-to-expensive cascade

The nascar_on_fox profile runs up to five passes. Each one can end the frame early, so the expensive vision model only sees frames the cheap checks couldn't settle. Ordering is the whole trick: a template match costs milliseconds, a full LLM prompt costs a large fraction of the capture interval.

05 — COMMITTING A DECISION

Classifying a frame ≠ switching the TV

A single wrong frame must not yank the picture away mid-battle for the lead. The state layer between classification and the matrix exists entirely to absorb the classifier's mistakes.

Debounce

Twice, or not at all

The same label has to come back on two consecutive frames before the committed state flips — unless the call came from OpenCV, which is trusted enough to act immediately.

unknown handling

Uncertainty doesn't reset

An unknown result is ignored rather than recorded, so a momentary parse failure between two agreeing frames doesn't restart the debounce count.

Self-instrumenting

Save the near-misses

When debounce blocks a change that looked real, that frame batch is written to disk tagged suspicious_debounce — the classifier's disagreements become the training-data pile.

Human override

"That's wrong"

One button on the status page corrects the label, saves the frames, switches immediately, and suppresses auto-switching for 30 seconds so the next bad frame can't undo it.

Live view

Status by SSE

/is_ad streams current state to any device on the network — useful as a second-screen readout while you're actually watching the race.

Output map

Two mappings, swapped

ad → {A:1, B:4}, content → {A:4, B:1}. Both outputs are written on every switch, so the two screens trade sources rather than one going dark.

06 — WHAT'S ACTUALLY HARD

The failure modes are the interesting part

Ads that look exactly like the race

The single hardest case. A tyre or truck commercial is full of race cars and reused broadcast footage. The tells are subtle — a missing network bug, a slightly different grade, a logo lockup — and OpenCV has little to grab onto.

The LLM is confidently wrong here almost every time: it sees race cars and says "racing".

Racing content that isn't racing

The mirror image: driver interviews, pit-lane walk-ups, the commentary booth. No cars on track, so the naive signal says "ad" — but switching away from them is exactly wrong.

Networks are inconsistent

Graphics packages change between events, and even within a broadcast the same overlay appears at different sizes and positions. Template matching is tuned against 1920×1080 crops, so every frame is resized to that first — and a graphics refresh can break a profile outright.

pHash overrides underdeliver

The correction system stores a perceptual hash per corrected frame, but only matches near-identical images. Commercials cut constantly, so the odds of screenshotting the same instant twice are low. Honest verdict: limited effectiveness in practice.

07 — RUNNING IT

Stack and moving parts

Docker Compose

Three containers

llama (CUDA vision model) · hdmi-matrix-control (serial bridge, needs the /dev/ttyACM0 device) · receiver (the FastAPI app, port 11679).

Server

Python ≥ 3.14, uv

FastAPI · OpenCV headless · Pillow · imagehash · the OpenAI client pointed at llama.cpp · Jinja2 for the review UI · Prometheus instrumentation · ruff + pytest.

Config

Layered

Defaults, then server/config.json, then DETECTOR_* environment variables. Everything is optional; the interesting knobs are the classifier profile and the output map.

Models tried

Vision matters more than size

Qwen3 Omni 30B-A3B is the current pick — it takes audio as well as images. Qwen3.5 4B Q4_K_M performs well for far less VRAM. Gemma 4 vision classified poorly.

Observability

Two histograms

classification_time_seconds and switching_time_seconds, so you can see whether inference is keeping up with the capture interval.

Scope

Deliberately narrow

Firefox on Linux, one HDMI multiviewer model, state held in memory and lost on restart. It's a single-household appliance, not a product.
